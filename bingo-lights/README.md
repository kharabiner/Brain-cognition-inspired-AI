# bingo-lights

버튼을 눌러 3×3 전구판에 정해진 빙고 줄을 만드는 태스크입니다. 한 문제는 5라운드이고, 라운드마다 **조건 · 규칙 ·
목표**가 모두 바뀝니다. 규칙과 목표는 알려 주지 않으며, 모델은 제출할 때마다 받는 피드백으로 찾아야 합니다. 라운드가
바뀐 뒤에도 직전 규칙을 따르는 오답(지속적 오류)이 얼마나 나오는지로 적응을 잽니다.

## 태스크 구성

| 구성 | 내용 |
|---|---|
| 조건 | 버튼 5개의 배선표: 버튼마다 켜는 전구와 끄는 전구. 매 라운드 네 칸씩 바뀌고, 질문마다 보여 줌 |
| 규칙 | 금지 전구 하나: 누르는 도중 한 번이라도 켜면 위반(끝에 다시 꺼도 위반). 매 라운드 바뀜. 숨김 |
| 목표 | 완성할 빙고 줄 한두 개(정확히 그 줄만). 매 라운드 한 줄 빼기 또는 더하기. 숨김 |
| 피드백 | 완성된 줄과 틀린 전구 번호. 목표 오류와 규칙 위반을 구분하지 않음 |

- 모든 전구가 꺼진 상태에서 시작하고, 버튼은 누를 때마다 켬 · 끔을 덮어씁니다(그대로인 칸은 두고). 모델은 누를
  버튼 순서를 한 번에 제출합니다. 피드백 예: `Bingo lines: 1-2-3 and 1-5-9. Wrong at lights 5 9. Not the answer.`
- 라운드마다 T=10번 안에 연속 k=2번 맞혀야 다음 라운드로 넘어가고, 못 넘어가면 그 문제는 거기서 끝납니다.
- 지속적 오류는 직전 금지 전구는 한 번도 안 켜고 지금 금지 전구를 켠 오답입니다. 라운드 PER은 지속적 오류 수 ÷
  채점된 제출 수(R2~R5), 문제 MPE는 그 문제의 PER 평균, 전체 MPE는 문제 MPE의 평균입니다.
- 생성 보장(전환 1200곳 모두, `bench/verify.py`)
  - 직전 라운드의 정답(3번 이하)은 어느 것을 다시 내도 지속적 오류
  - 직전 · 지금 금지 전구를 둘 다 피하면 줄을 하나도 못 만듦
  - 새 목표를 가장 적게 눌러 만드는 답은 직전 금지 전구를 켜고 지금 금지 전구는 안 켬
  - 옛 목표를 3번 이하로 다시 만드는 답도 절반 이상이 지속적 오류
  - 결과를 고치는 데 직전 금지 전구가 필요 없음

## 폴더

| 경로 | 내용 |
|---|---|
| `bench/engine.py` | 배선, 누름, 빙고 줄, 판정 |
| `bench/generate.py` | 문제 생성 |
| `bench/verify.py` | 생성 보장 검사(생성기의 판단을 쓰지 않고 엔진으로 다시 셈) |
| `bench/prompt.py` | 모델에게 주는 글 |
| `bench/runner.py` | 모델 실행 |
| `bench/drivers.py` | Anthropic · OpenAI API 연결 |
| `bench/score.py` | 실행 기록 채점(MPE, 우연 기준) |
| `bench/selftest.py` | 판정과 글 자체 검사 |
| `bench/make_human.py`, `bench/human_runs.py` | 사람용 페이지 만들기, 사람 결과를 실행 기록 형식으로 바꾸기 |
| `episodes/episodes.json` | 문제 300개(Q001~Q300) |
| `human/bingo-lights.html` | 사람용 페이지(10문제) |

## 실행 순서

```bash
cd bingo-lights
python3 bench/generate.py 300 20261028 8   # 문제 300개 (씨앗 20261028, 병렬 8) → episodes/episodes.json
python3 bench/verify.py                     # 생성 보장 검사
python3 bench/selftest.py                   # 판정과 글 자체 검사

pip install -r requirements.txt             # 모델 실행에만 필요
export ANTHROPIC_API_KEY=... OPENAI_API_KEY=...
python3 bench/runner.py claude-opus-5-5 --start 0 --episodes 100   # → runs/<시각>/ (동시 10문제, --jobs 로 바꿈)
python3 bench/score.py runs/<시각>
```

- 문제 번호마다 씨앗이 따로 정해져 있어, 같은 씨앗이면 같은 문제가 나옵니다(파이썬 3.13에서 확인). 생성기는
  `episodes.json`에 이미 있는 번호를 건너뛰므로, 처음부터 다시 만들려면 그 파일을 옮겨 두고 실행합니다.
  8코어에서 300문제에 7시간쯤 걸립니다.
- 발표 결과는 기본 피드백(`--feedback lights`)입니다. `rows` · `inrows` · `graded`는 틀린 전구의 위치를 덜 알려 주는
  실험용 옵션입니다.
- 생성과 검증, 채점은 파이썬 표준 라이브러리만 씁니다.
- 실행 기록(`runs/`)과 사람 참가자 결과는 저장소에 올리지 않습니다(`.gitignore`).

## 사람 평가

`human/bingo-lights.html` 하나를 참가자에게 보내 브라우저에서 풀게 합니다. 모델과 같은 문제, 같은 예산, 같은 피드백을
쓰고, 규칙 · 목표 · 라운드 전환은 알려 주지 않습니다. 끝나면 참가자가 결과 JSON을 내려받아 돌려줍니다.

```bash
python3 bench/human_runs.py <내려받은 결과>.json   # → runs/human_<이름>_<시각>/
python3 bench/score.py runs/human_<이름>_<시각>
```

페이지의 열 문제(Q006 Q032 Q040 Q056 Q059 Q062 Q067 Q077 Q083 Q099)는 Q001~Q100에서 R1을 푼 모델 수로 층을 나눠
뽑았습니다(`make_human.py --runs`). 층을 나누는 데 모델 실행 기록이 필요하므로, 같은 페이지를 다시 만들려면 그
기록이 있어야 합니다.

  Sonnet 20.8%.
