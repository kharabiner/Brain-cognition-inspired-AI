# water-pipes

3×3 격자의 파이프 타일을 눌러 돌려, 물이 정해진 색 칸에 닿게 하는 태스크입니다. 한 문제는 5라운드이고, 라운드마다
**조건 · 규칙 · 목표**가 모두 바뀝니다. 규칙과 목표는 알려 주지 않으며, 모델은 제출할 때마다 받는 피드백으로 찾아야
합니다. 라운드가 바뀐 뒤에도 직전 규칙을 따르는 오답(지속적 오류)이 얼마나 나오는지로 적응을 잽니다.

## 태스크 구성

| 구성 | 내용 |
|---|---|
| 조건 | 3×3 타일 배치: 파이프 모양, 물 1칸, 색 칸 3개(빨강 · 노랑 · 파랑), 돌 0~1칸. 매 라운드 새로 배치하고, 질문마다 글로 보여 줌 |
| 규칙 | 같은 타일을 이어 누르는 횟수: ×1 · ×2 · ×3+ 가운데 하나. 숨김 |
| 목표 | 물이 닿아야 할 색 칸 조합(나머지 색 칸은 말라 있어야 함). R1은 세 색 모두, 그 뒤 매 라운드 바뀜. 숨김 |
| 피드백 | 물이 닿은 색, 틀린 타일 번호, 정답 여부. 틀린 이유는 알려 주지 않음 |

- 타일을 한 번 누르면 시계 방향으로 90° 돕니다. 모델은 누를 타일 번호의 순서를 한 번에 제출합니다.
- 라운드마다 T=10번 안에 연속 k=2번 맞혀야 다음 라운드로 넘어가고, 못 넘어가면 그 문제는 거기서 끝납니다.
- 지속적 오류는 직전 라운드의 규칙을 지킨 오답입니다. 라운드 PER은 지속적 오류 수 ÷ 채점된 제출 수(R2~R5),
  문제 MPE는 그 문제의 PER 평균, 전체 MPE는 문제 MPE의 평균입니다.

## 폴더

| 경로 | 내용 |
|---|---|
| `bench/engine.py` | 판, 회전, 물 흐름, 판정 |
| `bench/generate.py` | 문제 생성 |
| `bench/verify.py` | 생성 보장 검사(생성기의 판단을 쓰지 않고 엔진으로 다시 셈) |
| `bench/prompt.py` | 모델에게 주는 글 |
| `bench/runner.py` | 모델 실행 |
| `bench/drivers.py` | Anthropic · OpenAI API 연결 |
| `bench/score.py` | 실행 기록 채점(MPE, 우연 기준) |
| `bench/selftest.py` | 판정과 글 자체 검사 |
| `bench/make_human.py`, `bench/human_runs.py` | 사람용 페이지 만들기, 사람 결과를 실행 기록 형식으로 바꾸기 |
| `episodes/episodes.json` | 문제 300개(W001~W300) |
| `human/water-pipes.html` | 사람용 페이지(10문제) |

## 실행 순서

```bash
cd water-pipes
python3 bench/generate.py 300 20261025 8   # 문제 300개 (씨앗 20261025, 병렬 8) → episodes/episodes.json
python3 bench/verify.py                     # 생성 보장 검사
python3 bench/selftest.py                   # 판정과 글 자체 검사

pip install -r requirements.txt             # 모델 실행에만 필요
export ANTHROPIC_API_KEY=... OPENAI_API_KEY=...
python3 bench/runner.py claude-opus-5-5 --start 0 --episodes 300   # → runs/<시각>/
python3 bench/score.py runs/<시각>
```

- 같은 명령, 같은 씨앗이면 같은 문제가 나옵니다(파이썬 3.13에서 300문제 모두 확인). 판 후보를 병렬 일꾼마다 따로
  모으므로 병렬 수(8)도 같아야 합니다.
- 생성과 검증, 채점은 파이썬 표준 라이브러리만 씁니다.
- 실행 기록(`runs/`)과 사람 참가자 결과는 저장소에 올리지 않습니다(`.gitignore`).

## 사람 평가

`human/water-pipes.html` 하나를 참가자에게 보내 브라우저에서 풀게 합니다. 모델과 같은 문제, 같은 예산, 같은 피드백을
쓰고, 규칙 · 목표 · 라운드 전환은 알려 주지 않습니다. 끝나면 참가자가 결과 JSON을 내려받아 돌려줍니다.

```bash
python3 bench/human_runs.py <내려받은 결과>.json   # → runs/human_<이름>_<시각>/
python3 bench/score.py runs/human_<이름>_<시각>
```

페이지의 열 문제(W094 W162 W167 W187 W242 W100 W220 W240 W265 W273)는 R1을 푼 모델 수로 층을 나눠 뽑았습니다.
층을 나누는 데 모델 실행 기록이 필요하므로, 같은 페이지를 다시 만들려면 그 기록이 있어야 합니다.

## 결과 (v1.0, 2026-10-25~27 실행, W001~W300)

| Model | N | MPE, % | Mean error, % | API time, min | Cost, USD |
|---|---|---|---|---|---|
| GPT-6.1 Sol | 190/300 | 44.66 | 82.73 | 379.62 | 10.0751 |
| Claude Opus 5.5 | 158/300 | 51.10 | 84.69 | 1181.63 | 168.0420 |
| Claude Sonnet 5.5 | 116/300 | 45.03 | 87.60 | 899.20 | 79.4284 |

- N은 MPE에 들어간 문제(R1을 통과한 문제) 수와 전체 문제 수입니다. 세 모델 모두 reasoning effort medium, T=10, k=2.
- 우연 기준(같은 길이의 무작위 클릭이 직전 규칙을 지킬 확률): GPT 12.4% · Opus 14.6% · Sonnet 21.0%.
